## Дополнительные критерии Destka для технической приёмки

Все пункты ниже пока открыты. Исполнитель прикладывает дату, release SHA,
URL/trace без cookies, секретов и private object keys; отдельный reviewer
повторяет внешнюю проверку. Скриншот и HTTP 200 сами по себе не закрывают flow.

- [ ] A01 закрыт подтверждённой изоляцией runner; A02 принят и A03 проверен.
- [ ] Разрешено конкретное развёртывание; HTTPS destka.ru показывает приложение,
      www перенаправляет на выбранный HTTPS canonical origin без downgrade.
- [ ] Header/footer/CTA, creator → Wall, auth return, history и legal ссылки
      ведут на существующие страницы; неопубликованные тексты не выдаются за договор.
- [ ] Реальные creator/Wall/услуги с подтверждёнными правами; нет тестовых аккаунтов,
      фиктивного спроса, ненастоящих отзывов или обещаний доходности.
- [ ] Получатель понимает: покупается временное размещение контента; Slot не
      становится собственностью. Takeover может закончить предыдущее размещение.
      Срок защиты, дальнейшая видимость, конец Wall и модерация объяснены до оплаты.
- [ ] Текущая цена приходит из backend; показаны RUB, итог, срок quote/reservation,
      условия и конкретные версии документов. Stale quote/смена владельца требуют
      нового подтверждения; URL/DOM не могут изменить сумму или владельца.
- [ ] RU/EN, light/dark, mobile/tablet/desktop, keyboard и auth interruption
      проверены на фактическом релизе; Telegram/VK in-app проверены физически.
- [ ] Успешны upload → processing → approval → moderation → Free Claim → current
      holder → history, а также отказ, конфликт, retry и восстановление.
- [ ] До отдельного разрешения live checkout не создаёт реальные платежи, не
      показывает неработающие методы как доступные. Публичный тариф и описание
      услуги можно показывать после согласования, отдельно от активации покупки.
- [ ] Рабочие support/refund/privacy/abuse каналы и реквизиты опубликованы с
      одобрением; у покупателя есть понятный способ обращения.
- [ ] Restore, rollback, мониторинг и доставка реального аварийного уведомления
      доказаны; согласованы нагрузка, лимиты и ответственный за инцидент.

| Этап                                | Допустимо                                                                                                | Условие перехода                                                                 |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Разработка / sandbox                | Изолированные test payments и synthetic fixtures; без смешения с production                              | Review кода и real sandbox evidence; test key проверяется backend                |
| Публичный сайт до merchant approval | Реальные согласованные услуги/цены/документы и бесплатный core; покупка недоступна с честным объяснением | Сайт принят владельцем, checklist подтверждён внешним reviewer                   |
| Merchant onboarding                 | Владелец подаёт настоящие сведения и согласует условия в защищённом кабинете                             | Письменное merchant/KYB/contract approval; не green CI                           |
| Production acquiring                | Только отдельно разрешённые методы, live credentials через secret manager, approved receipt/refund model | EGO-77/99/101/102 и финансовые проверки; явное разрешение владельца на активацию |
| Платный пилот                       | Ограниченный принятый сценарий с работающими возвратами/учётом/поддержкой                                | Финансовые gates и отдельный GO; не только успешный один платёж                  |

`PAYMENT_MODE=live`, `PAYMENT_LIVE_ACTIVATION=approved` и production environment
— существующие технические preconditions, но они не являются доказательством
юридического/merchant approval. Не менять их по этому checklist. First-use и
OAuth activation тоже требуют отдельного разрешения.
